# Runtime qualification: web browsers

> Point-in-time evidence from a local throwaway stack. No remote project,
> real credential or email provider was used. It covers the web matrix in
> `runtimeProfiles.web`; iOS and Android are qualified separately.

- **Matrix:** Chromium, Firefox and WebKit, each at desktop (Playwright's
  desktop devices) and narrow (390 by 844, the `@narrow` tests)
- **Roles:** signed-out, user (`qa-regular`), management-only user
  (`qa-management`), limited admin (`qa-admin` narrowed for its spec to
  viewing the schedule and staff and approving requests, then restored),
  admin (`qa-admin`, every admin permission) and super admin
  (`qa-super-admin`, who signs in for the state specs)
- **Database:** a seeded throwaway Supabase stack on 55321 and 55322
  (`npm run db:migrations:rehearse -- --from 087 --seeded`), migrated
  through 088; the shared local stack was not used
- **Rate limiting:** a local Upstash-compatible store (`redis:7.4-alpine`
  behind `hiett/serverless-redis-http:0.0.10` on 127.0.0.1:8079) in place of
  CI's dedicated E2E database
- **App:** the production build started by `scripts/run-production-e2e.mjs`
  on port 3002, with only the variables CI sets (no `apps/web/.env.local`,
  so email, error reporting and analytics were off)
- **Runner:** `scripts/e2e/qualify-web-local.mjs`, Playwright 1.62.1, one
  worker, one retry

## Triage

- **Failed in run 1, fixed in the test:** "a Calm Haven sign-out propagates
  to another authenticated tab" in Firefox and WebKit. Signing out closes
  the realtime socket before it connects, and both browsers log that as a
  console error. The test already excused it, but only on CI's stack port
  (54321), so the throwaway stack's 55321 counted as a failure. The filter
  now accepts any loopback port. Not a product defect.
- **Passed on a retry (WebKit, not repeated):** in run 1, "qa-management
  gets the same read-only surfaces plus the management roster" found the
  Shift details dialog still open 15 seconds after Escape; in run 2,
  "starts an impersonation session from the portal" timed out waiting for
  the sign-in page's load event. Each test passed in the other run and on
  its retry, so neither is recorded as a finding.
- **Skipped by design:** "leaving a page while its session check is in
  flight keeps the navigation" runs only in Firefox, which alone cancels the
  leaving page's requests; "shows the Shuffle loading screen while
  navigating to Schedule client-side" runs only in Chromium, whose network
  throttle is the only way to observe Next's loading fallback.

## Reproducing

Start the throwaway stack and the Redis pair, move `apps/web/.env.local`
aside, then:

```bash
E2E_STACK_WORKDIR=<rehearsal workdir> \
E2E_UPSTASH_REDIS_REST_URL=http://127.0.0.1:8079 \
E2E_UPSTASH_REDIS_REST_TOKEN=<local token> \
node scripts/e2e/qualify-web-local.mjs <summary.json>
```

`node scripts/e2e/qualify-web-local.mjs --record <summary.json> <this record> <commit>`
writes the manifest's `runtimeEvidence` entries from a summary.
