# Mobile app icons that survive launcher masks, and one splash instead of two

**Type:** Fix

**Status:** verified

> Built in chat on 2026-09-18 rather than through `/fix`; this spec was written
> from the finished work so the archive records what actually shipped.

## The problem

The 16-cell grid mark was the mobile app icon. It runs to the edge of its
canvas, so iOS's squircle mask clipped the corner cells and Android, which
shows only the central 72/108 of an adaptive icon and guarantees just the inner
66/108 circle, cut the whole outer ring on every launcher shape.

Launching the app also read as two splash screens: the OS launch image (a
static grid mark at 100dp, dead-center, on a flat background) followed by the
JS `AppSplashScreen` (a 96px mark pushed up to make room for the wordmark, on a
gradient wash, with every cell snapping to the faint pulse floor). The native
launch image cannot be removed or animated on either platform.

On web, the post-login `AuthTransitionScreen` showed a 32px spinner; the
animated mark had been dropped from the auth handoff months earlier.

## The fix

Replace the mobile app icons with the DM Sans wordmark stacked as `dub` over
`grid`, white on brand blue, generated by a script so the art is reproducible.
Make the OS launch image the first frame of the JS splash: same mark geometry
and size, same position, matching starting opacities, with the wash and
wordmark fading in around it. Put the animated mark back on the web auth
transition screen. The in-app and splash mark stays the animated 16-cell grid;
only the launcher icon changes.

## Build steps

- [x] **1. Icon generator and wordmark icons**
  - Add `apps/mobile/scripts/generate-app-icons.mjs` (`npm run icons` in
    `apps/mobile`): Playwright Chromium plus the DM Sans 700 TTF already in
    `@expo-google-fonts/dm-sans`, drawn on a 1024 canvas, centered by ink and
    shrunk until the ink box fits Android's safe circle. `--preview <path>`
    writes a sheet of the icons under the iOS squircle and the Android circle,
    squircle, rounded, and themed masks.
  - Regenerate `icon.png` (opaque `#2563EB`), `adaptive-icon.png` and
    `adaptive-icon-monochrome.png` (white on transparent); set
    `android.adaptiveIcon.backgroundColor` to `#2563EB` in `app.json`.
  - Done when the iOS icon has no transparent pixel, the Android foreground's
    farthest ink is inside the 66/108 safe radius, the generator is
    byte-deterministic, and both home screens show the wordmark icon after
    `expo prebuild` and a rebuild.

- [x] **2. Seamless launch image to splash handoff**
  - Generate `splash-icon.png` and `splash-icon-dark.png` from
    `AnimatedDubGridLogo`'s exact geometry and `staticOpacity` pattern in the
    light (`#2563EB`) and dark (`#2075FF`) brand blues; set `imageWidth: 96`
    and the dark image on the `expo-splash-screen` plugin so the launch image
    matches `BRAND_ANIMATED_LOGO_SIZE`.
  - `AppSplashScreen` centers the mark on the whole screen (as the launch
    image does), hangs the wordmark below it instead of centering the pair,
    and fades the gradient wash in with the wordmark.
  - `PulseCell` starts at its cell's static opacity rather than the pulse
    floor so the first animated frame equals the launch image.
  - Done when the mark's pixel bounding box is identical in the launch-image
    frame and the JS-splash frame of a cold launch, and a release build shows
    no intermediate frame between them.

- [x] **3. Animated mark on the web auth transition**
  - `AuthTransitionScreen` renders `AnimatedDubGridLogo` in place of
    `ButtonSpinner`, at the same default size as `ScheduleLoadingScreen`.
  - Done when the "Signing you in" and "Loading your workspace" screens show
    the pulsing mark and the existing screen test passes.

## Verify

- Icons: iOS simulator home screen and Android emulator app drawer show the
  `dub` / `grid` icon.
- Splash: cold-launch the app; the mark should already be on screen when the
  wash and wordmark fade in, with no jump in size or position. Check light and
  dark mode.
- Web: sign in on a subdomain; the transition screen shows the pulsing grid
  above "Signing you in".
- Run `npm run icons` in `apps/mobile` twice; the PNGs must not change.
- Run `npm run type-check`, `npm run test:mobile`, focused
  `AuthTransitionScreen` tests, `npm run lint`, and `npm run build`.

## Not changed on purpose

- `splash-icon.png` keeps the grid mark (it is the animated splash's first
  frame, not a launcher icon); `logo-blue.png` and `logo-white.png` are
  untouched in-app assets.
- `icon-blue-on-white.png` is an unreferenced duplicate of the old icon, left
  in place.
- The web `apple-icon.png` still carries the grid mark and has the same iOS
  clipping; a follow-up if wanted.
- The logout `AuthSplash` stays a blank frame.
